## 1. Konteks
Web internal PT Putra Perkasa Abadi (site Adaro) menggenerate dokumen mutu (SOP, SP, IK, JSA) untuk 7 departemen. Pengembang magang; kode direview senior IT. Utamakan kode STANDAR, jelas, terdokumentasi. Development SUDAH berjalan (~Fase 2) — MENYELARASKAN, bukan mulai nol.

## 2. Tech stack (WAJIB)
Laravel 12 (PHP 8.2+) · **Inertia 2 + React 19 + TypeScript + Tailwind v4 + shadcn/ui** · MySQL 8 via XAMPP · Auth NRP+password · RBAC spatie/laravel-permission · PDF barryvdh/laravel-dompdf + setasign/fpdi · Ikon **lucide-react** (JANGAN emoji) · Rich text **quill 2.0.3** (npm sejak Fase 9, `import()` dinamis — hanya halaman wizard yang memuatnya; versinya dikunci karena markup keluarannya yang menentukan apa yang lolos `PembersihHtml` dan bisa ditata `ActivityPrintLayout`). Timezone Asia/Makassar (WITA).

Bootstrap 5 + Alpine + SweetAlert2 tinggal di SATU berkas, `layouts/app.blade.php`, yang sejak Fase 12 tak dipanggil siapa pun dan antre dihapus di Fase 13.1 (ditahan sampai `docs/CEKLIS-MATA-PER-PERAN.md` selesai — Blade lama adalah acuan matanya). Tak satu pun halaman baru boleh memakainya.

## 3. Konvensi kode (WAJIB)
- Controller & Model STANDAR Laravel (DocumentController, Document). DILARANG prefix C/M.
- **SATU set halaman untuk SEMUA jenis dokumen** — `resources/js/pages/Documents/{Aksi}.tsx`, route `documents.{aksi}`. Perbedaan antar-jenis (SOP/IK/SP/JSA/FK/PX) datang dari **schema JSON**, BUKAN dari halaman/route terpisah (§7). Konsekuensinya menambah jenis dokumen baru = menambah schema + (bila perlu) template cetak, TANPA menyentuh halaman/route.
  > Uji aturan ini: tambah satu seksi ke `document_types.schema_json` lewat SQL → seksi itu **harus muncul sendiri** di form tanpa satu baris kode pun disentuh. Kalau tidak muncul, form React sudah menyalin struktur skema jadi TSX statis — dan itu kehilangan fitur, bukan perubahan tampilan.
  > Aturan lama "blade per jenis (`sop/index`, `ik/index`, …)" SUDAH DIBATALKAN: ia bertentangan dgn §7 dan memaksa halaman diduplikasi tiap jenis.
- **Standar penamaan:** kata STRUKTURAL pakai Inggris mengikuti konvensi Laravel (`index`, `create`, `edit`, `show`, `store`, `destroy`); istilah BISNIS tetap Indonesia karena itu bahasa kerja PT PPA (`jabatan`, `revisi`, `pengesahan`, `peninjau`, `penyetuju`).
- **Nama route = nama halaman = nama method, satu banding satu.** Mis. route `documents.published` → `resources/js/pages/Documents/Published.tsx` → `published()`. Dilarang route Inggris menunjuk halaman Indonesia (dulu `documents.published` → `berlaku.blade.php`).
- Komentar & seluruh teks antarmuka: **Indonesia**.
- Logika di Service class. Validasi Form Request. Otorisasi Policy/Gate. PSR-12.
- Controller TIPIS. Bila sebuah controller melewati ~300 baris, pecah — orkestrasi berat pindah ke Service (mis. `PdfRenderer`, `DocumentWizard`).

## 7. Arsitektur & status terkunci
- Schema-driven: schema JSON per jenis = sumber tunggal form/preview/PDF. Lihat docs/schema-sop.json.
- Partial bersama _kop/_footer/_pengesahan. Logo public/images/logo-ppa.png (BISA diklik -> home).
- Isi = value_json per section (document_contents). Jangan kolom tetap per jenis.
- Urutan bangun: SOP dulu (sampai PDF utuh) -> IK -> SP -> JSA terakhir.
- Pengisian 2 STEP. PREVIEW di PANEL KANAN (bukan tab baru), update saat klik Preview, 1:1, scrollable, di form input & edit.
- Status: draft, waiting_for_review, in_review, rejected, pending_approval, Berlaku, Sedang Direvisi, obsolete.
  - Edit/Hapus hanya draft. Withdraw hanya waiting_for_review.
- Batalkan Revisi (oleh GL/peninjau di Tinjau Dokumen -> Status Revisi): dokumen rejected -> kembali in_review (GL periksa ulang). Dokumen tipe B "Sedang Direvisi" -> kembali Berlaku.
- Dua revisi: Tipe A (ditolak, menu Dokumen Revisi pembuat). Tipe B (dokumen Berlaku, Ajukan Revisi oleh SH/DH/PJO/Admin — BUKAN GL; draft revisi dimiliki pembuat asli/GL; versi lama disimpan document_versions, otomatis OBSOLETE saat versi baru disahkan).
- Roll-over Edisi/Revisi (Tipe B): revisi 0..5; revisi berikutnya = Edisi+1 Revisi 0 (angka 6 tak pernah tampil). Ambangnya SATU konstanta, `DocumentService::MAKS_REVISI` (naik dari 4 ke 5 atas keputusan pemilik K-B, `docs/planpreproduction.md` Fase 1) — tiga aturan validasi `no_revisi` MEMBACANYA, jangan menyalin angkanya lagi. `DocumentExportController::REVISI_TERTINGGI` masih 4 dan sengaja TAK ikut (berkas HARAM §14b): akibatnya kolom Rev 5 edisi lama belum tercetak di Daftar Induk. Nomor pada LEMBAR catatan revisi (`sections.catatan_revisi[].no_rev`) TAK ikut ambang ini: sejak keputusan pemilik 2026-09-07 ia naik seperti angka biasa tanpa batas atas, sebab ia menghitung urutan SESI revisi pada lembar, bukan versi dokumen. DocumentService::nextEditionRevision; deteksi "ini revisi" via versi lama sedang_direvisi bernomor sama (BUKAN no_revisi>0) + kolom revises_document_id.
- Dokumen lama (arsip) berlembar revisi: sesudah lembar CATATAN REVISI diisi, satu-satunya kelanjutan adalah SALIN ke wizard (pilihan "gabung" dicabut, rencana pra-produksi Fase 2 / K-E — `ArsipPenggabung.php` tidak dihapus, cuma kehilangan pemanggilnya). Draft salinan ditandai `documents.salin_arsip_at`, dan saat DIKIRIM ia langsung Berlaku tanpa tinjauan (`DocumentService::tandaiTerkirim()` → `sahkanSalinanArsip()`; versi unggahan lamanya otomatis obsolete). Peninjau/penyetuju TETAP wajib dipilih di Langkah 2 — namanya yang tercetak bercap APPROVED di blok pengesahan.
- Draft revisi Tipe B: wizard punya langkah EKSTRA "Log Revisi" di akhir (Simpan/Kirim pindah ke sana); mengisi lembar CATATAN REVISI (NO|NO.REV|TANGGAL REV|HAL.|CATATAN, format docs/Lembar Revisi.docx) yang tercetak di halaman DEPAN PDF, barisnya terakumulasi lintas revisi.
- Reject approver -> feedback wajib -> balik ke GL -> rejected; peninjau yang meloloskan dinotifikasi.
- PDF: kop memuat "Halaman X dari Y" (di-stamp page_text DomPDF, koordinat terkalibrasi di DocumentController::stampPageNumbers). Kop JSA + Edisi, BERULANG tiap halaman via position:fixed (bukan thead — DomPDF memindahkan tabel utuh ke hal. 2); blok info+TTD JSA hanya hal. 1. Saat Berlaku SEMUA TTD bercap APPROVED (pakai published_at). Tata letak dikunci PrintLayoutTest (membaca stream PDF nyata).

Alasannya: `PdfRenderer` punya singgahan disk berbasis sidik jari dokumen dan konstanta `versiKodeCetak()`. Selama kode cetak tidak berubah, PDF hasilnya identik — dan itulah satu-satunya jaminan "ekspor dokumen tetap sama".

**Dua penjaga, jalankan tiap fase:**
- `md5sum -c C:/baseline-smartpro/mesin-cetak.md5` — 23 berkas mesin cetak + template, harus lolos penuh.
- `php artisan smartpro:cetak-baseline` — merender ulang seluruh dokumen non-arsip dan membandingkannya dengan `C:\baseline-smartpro\pdf`.
